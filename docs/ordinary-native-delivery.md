# Ordinary native delivery integration

September 30, 2026. Offline engineering; no provider requests or credentials.

An exact, explicitly selected `native-http-v2` contract now applies to ordinary
Kalshi/Polymarket US collection, existing modern bounded discovery, and unified
native/aggregate source settings. The shared reader enforces the same finite
2 MiB entity/decoded response, 4 MiB HTTP plaintext, 6 MiB source HTTP totals,
16 MiB JSON expansion, depth 32, 100,000 structural tokens and 256 KiB intake.
Omitting the contract preserves the historical reader. Old sealed profiles and
target-v1 specifications cannot acquire this policy implicitly; changing the
contract or candidate invalidates their approval.

The shared route/envelope classification supports ordinary events, markets,
league metadata, documented league event listings, arbitrary `/v1/events/{id}`
details and `/v1/market/id/{id}` details. No selected event or its pregame window
organizes the transport. Whole valid envelopes are separate from requested
identity, semantic terms, event state, eligibility and admitted books. A complete
closed/started response can answer delivery while remaining excluded from book
admission. Detail responses preserve their original raw bytes, hashes and actual
request parameters; only the catalog view unwraps the singular entity. A detail
market cannot establish its event without an independent exact parent listing.

Ordinary REST uses the explicitly validated finite HTTP timeout. A complete
non-200 response records its precise status failure and no usable metadata, then
returns to the existing request owner for any permitted bounded status recovery.
Redirects, framing, peer-close, encoding, JSON, resource and credential-echo
failures retain their distinct reasons. The existing no-retry diagnostic and
gap slice keep their own attempt policy. HTTP/accounting does not confer provider
identity or semantic review.

Explicit `native_scopes` now reuses the retained typed source catalog: 110 exact
Kalshi series keys across 46 required cells, with every requested cell and each
attempted/omitted selector recorded. One catalog opportunity per cell precedes
alias expansion; integrated winner metadata remains prioritized. US collection
reuses evidenced league/game selectors, giving each requested sport one finite
five-game page before market metadata. A hard per-generation allowance is
checked before each scoped HTTP attempt; scoped requests do not retry. Known
series keys locate metadata but do not supply missing line orientation, period
boundaries, championship field/award or season terms. Those predicates and
semantic review remain separate admission requirements. Metadata-only discovery
can select the same explicit scopes under v2 without changing historical probes.

Source catalogs are measured on every changed generation with last/peak retained
bytes, exact limits and admission decisions. The existing shared queue admission
gate now also applies to ordinary v2 inventories before publication. Complete
raw receipts remain durable before normalization, semantic review or subscription.

selection, strict contract types and timeout rejection, arbitrary completed

with exact charges, generation accounting, and ordinary Start/Stop with a
