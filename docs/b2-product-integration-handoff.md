# B2 — connect coverage collection to ordinary Predict comparisons

September 20, 2026. **Implementation handoff delivered; B2 NEXT, not implemented. B1 COMPLETE. Beta NOT READY FOR SIGNOFF.** Read with the [coverage matrix and dependency ledger](b1-coverage-matrix.md), [delivery plan](data-coverage-plan.md) and [beta scope](product-roadmap-review.md).

## Visible outcome and smallest coherent change

One existing dashboard should follow its explicitly started coverage session, display discovered events/markets and per-source gaps, update supported current comparison rows as retained books arrive, then freeze and reopen the same observations after Stop. Add a small shared session projection and format-aware history reader; reuse the collector, adapters, normalized records, event matcher, calculation functions and UI. No replacement architecture, database migration, new standalone diagnostic, new source activation or broader market-math implementation is needed for B2.

B2 proves the connection with retained observations and clearly labeled fixtures, including a third venue and two reference roles. It does not claim four production venues, six-sport economic support, or actual model/Pinnacle acquisition. Those are B3–B5. It must expose unsupported market rows rather than reinterpret them as NFL winners.

## Proposed product contract v1

Use existing retained rows as the source of truth. The following is an additive projection/API contract, not a second observation journal. Decimal prices, quantities, lines and monetary values serialize as strings; missing values are null plus a reason.

| Object | Required fields and invariants |
|---|---|
| Session | `schema_version`, `session_id`, `data_mode` (real/sandbox/synthetic), `view_mode` (current/saved), `state`, `started_at`, `stopped_at`, `durable_cursor`, `projection_revision`, `mapping_revision`, calculation/fee/rule revisions. Evidence mode and current/saved are independent dimensions. |
| Cursor | Existing ingress ID plus journal-chain identity; segmented sessions also carry segment/index or equivalent stable verified position. Never use wall time alone for ties. Save source references and mapping revisions so historical reopening cannot silently adopt today's mapping. |
| Source | `source_id`, `venue_id` or null, `provider_id`, `origin_id`, `role` (prediction/model_reference/bookmaker_reference/manual/research), environment and evidence classification. Pinnacle via an aggregator retains both IDs; two frontends to one origin do not become independent sources. |
| Event | Stable canonical ID or unresolved native key; sport, competition (including gender/division), season, stage, participants and roles, scheduled-start revision, native event bindings and match-decision evidence. Do not merge by display names alone; doubleheaders and reschedules remain distinct/reviewable. |
| Market | Canonical group ID or unresolved native key; event or futures competition/season scope; family, explicit period, signed line and subject where applicable, phase, rules-profile revision, native market IDs. Full game, regulation-only, H1, H2, inning range and period index must never collide. Futures add category, horizon and participant field; missing definitions remain unknown. |
| Outcome | Stable ID scoped by source + event + market/strike + native outcome, canonical participant/side predicate and payout meaning. A NO outcome means the complement of its native proposition, not automatically another team's win. Multi-outcome futures must not be reduced to an arbitrary pair. |
| Observation | `observation_id`, durable cursor/raw hash, native refs, receipt/source time, nullable model-as-of and delay information, native price/units, normalized ask/depth/quantity units, sync, market state, source generation. Preserve original bytes and transformation/version refs. |
| Coverage/health | Per source and per market/group: discovered, eligible, selected, requested, acknowledged, receiving, usable; completeness and generation/as-of; exclusions and reason codes. Unknown counts are null, not zero. Connection, reconstruction, receipt freshness and economic eligibility are separate. |
| Comparison | Stable market-group + outcome-leg IDs; retained cutoff, original observation IDs, requested/modeled quantity, fee/settlement basis, result/status/reasons. References never appear as purchasable Arb legs. Missing probability remains `Assumption needed`; unsupported rules/fees/depth make net outputs unavailable. |
| Reference | Source/provider/origin, target market/outcome identity, model version/as-of, received/source times, delay value or unknown, value kind (rating/margin/total/probability/native odds), conversion method, dependencies and raw provenance. A rating stays a rating. Receipt later than cutoff cannot enter historical EV. |

Reducer inputs: `session_started`, `coverage_inventory`, `market_selected`, `prediction_book`, group-scoped `source_health`, existing closure/safety records and `session_finished`, plus an additive versioned reference/coverage-status record where necessary. Initial legacy selection converts into an inventory view in memory. Use the native `market_selected.raw.ref` and inventory provenance to bind metadata; do not rely on the bootstrap event in `run-spec.json` for coverage books.

Example behavior: a full-game winner for NFL event E groups K and US by verified event identity, while two K YES/NO outcomes remain tied to their own market. A third fixture source joins that group without changing E's canonical identity. E/H1 and E/full-game spread -3.5 remain distinct catalog groups and show unsupported economics until B5. An MLB innings market does not map to H1. Unresolved events stay visible in source coverage, with no fabricated pair.

## Health, updates, Stop and history rules

- Freshness advances with display time even when no packet arrives; a quiet book must visibly age. Preserve current 30-second receipt and 5-second cross-book-skew behavior where applicable; distinguish these policies from source delay and from model validity. Do not apply exchange freshness thresholds blindly to deliberately delayed references.
- Group disconnect invalidates only its bound markets; healthy markets elsewhere on the venue must not be overwritten. Unknown/stale/unsynchronized/inactive/no-purchasable-ask states carry explicit reasons. Missing provisioning is `not_configured`; undocumented coverage is `unknown`; a complete permitted empty listing is `no_listing`; incomplete traversal is `partial`. None is a numeric zero opportunity.
- Catalog coverage is independent of pairability. Show unmatched, ambiguous, not selected due to bounds, unsupported family/period, stale and closed rows. Source failures must not hide valid comparisons among other sources. Per-leg health gates comparisons; no overall “connected” shortcut.
- Explicit Start creates one current session; no start on reload/restart, no credential access for disabled sources, no automatic retry. Keep finite configured bounds and no overlapping collector/finalizer. UI polling has no collection ownership.
- Stop closes intake, joins producers, drains acknowledged records, finalizes/replays and releases ownership in the existing order. Freeze new market observations at closure; allow terminal status changes without new market acquisition. During saving, show frozen/saving rather than old rows as current. Start remains disabled through cleanup. Failed finalization stays visibly incomplete and retains evidence.
- Reopening dispatches by manifest format and validates hashes. Flat coverage `report.json` and segmented `history/manifest.json` are handled by their own readers; old `saved_rows` allowlists are not simply disabled. Interrupted verified prefixes can be displayed as incomplete with gaps, never “Completed.” Saved as-of math uses retained cutoff time, not today's freshness clock. New schema/projection revision must not overwrite or silently relabel old evidence. Unknown format is an explicit unsupported saved package.
