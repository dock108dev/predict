## U3 service interfaces and ephemeral admission

`CurrentService.start(config, authority, quota_store)` acquires one exclusive process/runtime lock, creates a fresh runtime ID, starts exactly one worker per native source and one aggregate scheduler slot, then publishes connecting state. Multiple tabs/filters/leases never call start. A competing process reports ownership conflict instead of acquiring duplicate paid/native work. Close of an individual tab releases its subscriber and lease; it does not stop sources. App shutdown or explicit admin stop owns service shutdown. When there are no subscribed users, metered aggregate dispatch is idle-paused; native lifecycle follows configured attended-session policy.

`Admission.normalize(envelope)` validates source ID, native IDs, exact binding, units, finite values, timestamp meaning, state and source epoch/sequence under existing provider contracts. It returns a typed observation or sanitized rejection. Partial/malformed/incomplete observations never replace valid quotes. Catalog deletions and market terminal states are explicit tombstones. Per-source epoch requires full synchronized image after disconnect/resync before dependent calculations resume. Provider monotonic sequences reject duplicates/regressions; routes without sequences use source-epoch serialized receipt order and documented snapshot semantics, with source time preserved independently.

`LatestStateSink.commit(observation)` serializes admission through one bounded service queue and calculates an immutable candidate update. Enforce bounds *before* publishing; atomic swap state + service sequence + quote revisions, then publish a notice. A reducer exception discards the candidate and records a bounded issue; no partial advance/acknowledgment. In-memory commit acknowledgment means accepted latest state, not durable observation storage. Health-only transitions advance state revision but cannot reprice quotes or reset source times. Identical images do not imply new source observation time unless the provider supplies an actual new quote clock with documented meaning; quote value/depth revisions remain separate from freshness.

`JournalSink.commit` retains existing fsynced ordering, acknowledged observer/cursor and exact replay chain. Factor the reusable reducer so it accepts normalized input and an explicit commit context, without depending on journal paths, chain rebuilds or finish exports. Do not turn off journal writes underneath `ContinuousSession`: projection/error recovery/resource reservation currently assumes them. Runtime projection error has no historical reconstruction fallback: keep the last valid view visibly degraded, mark affected source resyncing, then get a fresh image; independent healthy sources continue.

Provisional resource policy to implement and verify in U3: 200 admitted events, 2,000 exact market groups, 16,000 latest quotes, 64 MiB serialized latest state, 2,048 ingress records / 8 MiB, eight subscribers / 1 MiB pending per subscriber, eight immutable leases / 2 MiB total / 300s. Limits count actual encoded bytes and objects; unknown/over-limit entries are excluded with bounded reasons, not silent identity truncation. Keep a 200-record / 1 MiB rolling sanitized issue buffer. Runtime connections/request/body/RSS bounds must retain transport safety and use a separately versioned policy with concrete measured limits at U3 dispatch. These are engineering defaults, not measured cadence or readiness claims.

When full, coalesce complete replaceable snapshots by exact source/instrument where provider semantics permit; never coalesce incremental book deltas across gaps. Reject/backpressure and resynchronize incremental sources. Bound catalogs and rediscovery pagination separately. Retire expired/terminal events deliberately; leases preserve only their bounded frozen review. No per-quote permanent journal or database is introduced. Persist only operational config/standing-authority binding, preferences, lock ownership and quota reservations. Existing historical evidence remains preserved.

`CurrentService.close()` is idempotent: revoke admission epoch/stop accepting new work, cancel discovery/acquisition, close sockets and HTTP clients, bound task cleanup, reconcile or conservatively retain charged reservations, expire leases, publish stopped state and release lock only after no work can dispatch. Retain bounded cleanup failure evidence; if cleanup cannot establish safety, hold ownership and report an issue. Source recovery is independent with bounded provider-compliant backoff; authentication/entitlement/malformed/repeated-rate-limit conditions pause only the affected route. No unattended OS service, scheduled job, SLA or deployment is implied.

## U4 quota and scheduler interfaces

`QuotaStore.reserve(attempt_id, reset_period, maximum_cost)` runs durably and atomically before dispatch under shared ownership. Total nominal 500 monthly credits, shared by Novig/ProphetX/references and all diagnostics; keep 50 inside that ceiling for engineering. Provider fresh remaining/reset, local outstanding reservations and out-of-band spend bound admission. Unknown/contradictory accounting means paused metered flow, never fabricated remaining=500. Small durable rows survive restart; an ambiguous charged failure holds its reservation. A documented confirmed no-charge outcome may release it. Reconciliation never resets spend merely because the app restarted.

`AggregateScheduler.next_due(quota, users, scopes)` selects at most one global three-market batch every six hours when affordable, rotating useful sports. At three credits for one sport/three markets/one region-equivalent, 31 days costs 372 before extras; this is not six-hour polling of each sport. Reserve worst-case documented charge before the call and reconcile actual provider usage headers. A source header/reset anomaly pauses paid dispatch and surfaces a site issue while native sources continue. Hourly attended windows are allowed only if projected remaining-period operating allowance fits; no idle paid polling or automatic purchase.

`AggregateResponse.admit` normalizes both comparison venues independently from one supported sport-wide response; retain each bookmaker's original decimal string/source timestamp and shared response receipt. Missing Novig data does not discard ProphetX. Event identity/line/period/rules remain exact; unknown counterparts go to admin exclusions. Optional references are marked role reference. Broader periods/futures have distinct affordable scopes. Slower/next-due state is shared across tabs; filtering never changes paid schedule directly.

## U5 admin and issue interface

Admin snapshot is separate from ordinary price payload: runtime identity/candidate/policy, source scopes and states, last quote/receipt/projected timestamps, resync/backoff/next due, bounded admission/exclusion counters, source→receipt/receipt→projection/projection→browser latency where known, RSS/bytes/backlog and cleanup state. Shared Odds API used/remaining/reserved/reset/next-due and 50-credit reserve display unknown honestly. Source stop/pause/resume commands act on the same owner and respect safety/quota; sanitized raw/evidence links are local-only.

Issue schema `predict-site-issue-1`: issue ID, provider/site URL, affected venues, endpoint class without query secrets, runtime/attempt/candidate digest, first/last UTC time, league/market scope, category (`authentication`, `entitlement`, `offering_unobserved`, `budget_delay`, `identity_conflict`, `rate_limit`, `malformed_source`, `local_defect`, `cleanup`), sanitized status/code/observation, practical comparison impact, healthy independent paths, retries/backoff/charged/reserved credits, smallest engineering action and owner input only if needed. “No offering observed” is not proof of unsupported provider capability. Identify The Odds API and affected Novig/ProphetX separately. Never substitute international Polymarket.

## Follow-on gates and boundaries

U1 verifies ordinary routes/layout/local filters/keyboard and no retained fallback. U2 verifies exact originals, same/different lines, units/boundaries, references, coherent leases and existing math assertions. U3 uses fake faults first, then separately qualifies current Kalshi and Polymarket US beyond the finite 180-second lifetime, reconnect/rediscovery, multiple tabs, bounded memory/disk and clean shutdown. U4 fake quota tests precede small recorded live paid checks inside fresh remaining quota; no attempt repeats consumed authority. U5 verifies issues/admin security and ordinary/admin split. U6 integrates live evidence and explicit owner product acceptance.

Standing source authority is already granted; follow-on work records fresh candidate/scope/endpoints/attempt/budgets without another broad planning or permission gate. Stop at actual provider/safety/quota gates, keep healthy paths useful, preserve consumed approvals/captures/credentials/watch data. Local U0 engineering does not qualify automatic operation, hosted Linux, source cadence, account economics, or owner acceptance. The U0 task stopped at design. The subsequent authorized U1/U2 task implements the ordinary interface and current/lease semantics, then stops before U3 acquisition; no trading, purchase, deployment, commits or pushes.
