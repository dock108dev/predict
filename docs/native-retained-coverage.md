# Retained native comparison data

Saved readers verify the journal, manifests, selected reviews and dependency
hashes before projecting a retained native comparison. A saved cutoff describes
what was known then; it cannot establish present availability or fresh economics.

`dashboard/native_reviews.py` and the versioned indices under `app/reviews/`
bind exact retained records. `session_history.load` and `project_rows` accept
explicit interpretation versions; the original interpretation remains available.
A derived view must keep its original receipts and source identity distinct from
new provider observations.

The offline seal tool copies required review inputs, code and these format notes.
Its package is an input for explicit retained inspection, not ordinary app startup.
Required saved data stays in the repository where fixture or package readers need
it. Generated measurements, screenshots and internal planning notes are local
working output. See [development](development.md) for testing and [native review
records](native-review-records.md) for the record contract.
