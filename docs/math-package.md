# Predict mathematical package — September 29, 2026

This package completes the source-independent acquisition mathematics and exposes it in ordinary saved Details as **Settlement & allocation What-if**. Existing native calculations, source roles, original saved outputs, and accepted card layout are preserved. New calculations use `math-package-1`, `explicit-depth-1`, `settlement-portfolio-1`, `generic-fees-1`, `odds-cashflows-1`, and `reference-devig-1`.

## Cash and probability contracts

A quantity in the generic depth extension denotes a **$1 payout unit**. Native unit transformations remain in the existing adapters and native ladder engine. `odds_cashflows` also supports explicit non-$1 payout units. It never guesses a native stake/contract unit from published odds or bet limits.

The return denominator is incremental acquisition cash, including entry fees, plus the explicit reserve conservatively consumed in every state and separately prefunded worst settlement liability per leg when net receipts can be negative. Unused liability funding is returned, so it changes the cash denominator without being charged again as an expense. Previous account-position capital is excluded: netting calculates incremental commission relative to the supplied baseline. This is not total-account ROI. Known zero and negative results remain valid outputs. No-trade has zero net and an undefined percentage denominator.

Every leg explicitly supplies its fee policy (or unknown), quantity grid and minimum, level IDs/capacities, and per-state payout/settlement fee. A missing policy or material state amount stays unknown. `fraction` is a fraction of the $1 payout; `refund` returns a fraction of actual consumed stake; `split` combines payout fraction with explicit `refund_fraction`; `per_unit` supports an explicit gross cash amount. Entry fees are retained on refund unless the supplied settlement receipt explicitly models their return. The direct portfolio interface supports arbitrary explicit net receipts, including returned fees.

State labels are **joint settlement states**, not a claim that two venues settle identically. Include the branches where one venue voids while the other settles, conflicting postponements, partial/refunded payouts, or any other applicable exceptional state. The `complete` declaration is a supplied scenario assumption, never a verification of real terms. The UI labels all such calculations hypothetical.

Two-way bookmaker odds do not establish draw/push/void probability. A reference estimate is conditional on its complete quoted outcome set and carries the original odds, method, conditioning, source identity, receipt, source time and unknown upstream delay. To use it in What-if EV, scenario state names must equal the quoted outcome set and the user must explicitly acknowledge conditioning. It is never promoted to calibrated fair probability or a live signal.

## Search and partial fills

The solver enumerates zero plus each allowed positive grid quantity up to supplied depth, with no more than 10,000 evaluated allocations (default 4,096), additionally bounded to two million leg-state evaluations for large fields. Up to 1,024 explicit settlement states match the championship engine domain. Invalid shared-capacity, exclusive-alternative and final-level allocations are counted. Unknown objectives prevent a supported optimum claim. Results include top evaluated candidates and the exact modeled quantities; arbitrary requested quantities can be evaluated independently.

One fill per consumed price level is the explicit rounding model. Actual fragmentation can change rounded fees. Partial-fill exposure enumerates the selected allocation down to zero on each increment, including fills below the order minimum, bounded by the same evaluation budget; the 64 worst evaluated rows are displayed and domain completeness is separately reported. Off-grid fills and different fragmentation are not claimed covered. Neither a search result nor a scenario guarantees atomic fills.

## Ordinary workflow and preservation

Open a saved comparison's Details, then **Settlement & allocation What-if**. Inspect complete reference sets or load the clearly hypothetical example. Edit/import assumptions, enter explicit quantities or leave them blank to search, then calculate. A saved result belongs to its exact session/game/cutoff and remains separate from original capture files. Downloaded bundles retain inputs, method versions, binding, checksums and results; replay verifies both checksum and recalculated outputs. No background acquisition or watch is created.

Original saved calculations are not silently replaced. Existing native engine outputs still use their original fee and settlement bindings. New source-dependent applications can consume the completed generic engines only after exact input identity and evidence are supplied.

## Remaining source-dependent applications

- **Kalshi / Polymarket US native:** effective contract-specific settlement coverage, conflicting postponement branches, applicable fee/account precision and mandatory settlement charges, executable increment/fragmentation evidence, and qualified current state/timing where not retained. Generic arithmetic does not cure their existing conflict or qualify fees.
- **Novig / ProphetX aggregate comparison observations:** actual native listing linkage/effective rules, Novig fee units/market objects and applicability, ProphetX complete account/market netting plus rounding, executable depth/quantity units/minimum/increments, fill partition and source timing. Published bet limits remain non-executable observations.
- **Pinnacle / DraftKings / BetMGM reference-only:** complete contemporaneous quote sets are usable for conditional reference estimates. Native-target settlement equivalence, exceptional/push probability mass, calibrated model meaning and verified upstream freshness remain absent where not evidenced. They never become executable legs.
- **All 63 cells:** native bindings for remaining period/championship markets, effective period/completion predicates, championship season/category/award/complete-field identities and broader real observations remain as recorded in the existing coverage ledger. No sample absence removes a required cell.

Owner/commercial validation and beta signoff remain deferred. No acquisition, credentials, credits, outreach, trading, commit, push or publication is part of this package.
