# Scanner transition read v1

SC05 supplies `GET /api/scanner/transitions`. This additive, read-only protocol preserves scanner v1 and never performs provider acquisition or financial evaluation. The [schema](contracts/predict-scanner-transitions-1.schema.json) and [authored examples](examples/scanner-transitions-1/README.md) define its wire. These are local observations of the supplied universe, not proof of an opportunity's first market instant, complete market history, or current source qualification.

## Scope, continuity and meaning

Use the scanner's venue, sport, league, market, period, category, minimum edge and minimum supported discovery funding filters. They apply across every supplied row before any page selection. Find on this page and pagination do not change notification scope. Both venues must match. Unsupported dimensions return censored continuity and incomplete coverage. Scope hashes bind canonical sorted filters, version, server and epoch. Send the returned `cursor`, `scope`, `server_id` and `epoch` together on subsequent reads. There is no consumer registration, per-user financial graph or durable history.

Publications, rather than HTTP reads, compare compact economic/eligibility facts. Receipt-only clock churn, ordering and page visibility cannot create transitions. Stable identity is SC02's exact opportunity identity plus category row; the exact pair, dependency/economic revisions, original clocks, edge and observed deployed funding accompany each end of a transition. A category episode ID binds server/epoch, row and its observed start cursor. Different categories have separate qualifying episodes. SC06 must consume these definitions rather than count rows, polls or filter matches as births.

- `new`: a category starts qualifying after an observed complete evaluation of the same pair without that category. This is an observed qualifying episode, never a claim of first market birth.
- `first_observation`: the pair was absent from the previous complete supplied universe. Its earlier qualification is unknown and it is silent.
- `improved`: the same episode improves by at least 0.25 percentage points, or observed deployed funding increases by at least both 10% and $10 without reducing edge. Improvements have a 30-second per-row cooldown. Intervening changes coalesce; the seam does not accumulate subthreshold gains into a fabricated jump.
- `matching` / `no_longer_matching`: the same existing opportunity crosses the user's edge or size threshold. This does not start or end its category episode. A filter change itself returns a silent baseline.
- `withdrawn`: that category ceases qualifying while the same pair is still authoritatively evaluated. It does not assert that the native market was removed. `unavailable` means the pair left the evaluated universe; continuity of its qualification is unknown and sound is withheld.

Each event ID binds exact publication cursor and row. Repeated reads can return the same IDs; consumers deduplicate. Global episode identity is independent of a user's scope. The default client emits at most one quiet sound per accepted batch and is off until a deliberate enable action. It retains at most 512 IDs and 256 temporary five-second visual cues. It does not sound in the background. The client uses only events marked audible by this protocol; initial/reload/replay, filter changes, reconnect, gaps, overflow, unsupported scope and epoch resets are silent. Local sound never requests notification permission.

## Censoring and bounds

A complete evaluated supplied universe establishes a silent baseline. A pending financial turn is an intermediate observation, not proof of a withdrawal; it is coalesced until completion. Failed/unknown coverage, capture failure, expiry, Stop or epoch/server change discards continuity. The next complete observation starts silently. Cursor loss, a future cursor, wrong scope, missing retention or overflow returns `continuity=censored` and no events. `coverage_complete` describes the current observation and is false during pending or uncertain coverage; it never means all provider markets were observed. Missing coverage cannot establish checked-zero, duration or a complete event history. Current ticket authority is withdrawn independently of notification history.

One replaceable baseline holds at most 4,096 compact category facts / 8 MiB, with at most 2,048 supplied pairs. A bounded journal, mirrored in the latest SQL publication, retains at most 128 batches / 2 MiB; each batch and returned event set holds at most 256 events / 512 KiB. A response is bounded by 512 KiB plus 4 KiB metadata. Overflow censors rather than truncating a purported complete stream. State maps are pruned to live rows; no consumer state is retained. App reads load the latest SQL publication and scan at most the retained 128 batches, with no provider calls or financial evaluation. Missing publication continuity is censored. [Runtime contract](data-app-runtime-contract.md). The scanner's ordinary publication worker owns comparisons. This is a transport continuity buffer for SC05 and SC06, not a second SC06 episode store or raw/report archive.

The client schedules one transition read after each accepted scanner cycle, alongside one selected-ticket status/renewal owner. There are no row pollers. Reads are aborted on scope change, suspension and supersession; a 1.8-second transition deadline and bounded streaming body apply. Failure resets continuity before reconnect. The scanner's compatibility and revision application budgets remain independent of this optional read.

## SC06 integration boundary

SC06 owns bounded persistent episode summaries and the full-finance 500-event causal performance proof. Carry category/opportunity/pair/server/epoch, original clocks, observed transitions, scope/coverage and censoring into that work. Initial rows and first observations are left-censored; absent coverage is a gap, not a withdrawal or checked-zero. SC06 should observe the same publication seam directly for summary accounting; repeated HTTP reads must not create episodes. The seven-day / 10,000-episode / 10 MiB summary limits include indexes and auxiliary data. SC05 adds no durable episode table or migration.
