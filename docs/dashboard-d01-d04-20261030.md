## Implemented D02–D04 path

The existing background board publisher atomically writes a replaceable
`latest_dashboard` projection alongside each accepted publication. It retains
primary numeric candidates (including zero/negative), blocked reason counts,
and separately counted input/search refusal units. It does not turn refused
candidate classes into invented pair rows. The projection is included in the
SQL storage allowance. Existing price, accounting and control tables are retained.

`GET /api/boards/dashboard` captures both views at one SQL snapshot. The rolling
window is `read_at <= start_at < read_at + 72 hours`. It reads compact published
counts, and validates full dependency neighborhoods only for numeric candidate
games. No calculations or acquisitions run in this route. Every supported
candidate in the window participates in exact Fraction ranking, with ties by
start, game identity and result identity. The response exposes ranking basis,
ordered identities, window, revision, as-of, counts, blocked reasons and errors.
All supported candidates are returned so client filters can rank across the
entire eligible window. The existing 8 MiB response guard remains; high numeric
candidate volume still requires load qualification, not a relaxed deadline.

EV uses `buffered_return_percent` only when `buffered_ev_usd` is numeric/current.
Opposing pairs use `buffered_complete_minimum_return_percent` only when the
complete modeled minimum is supported/current and venues differ. Hypothetical
modeled-winner scenarios, decisive-only metrics and gross prices cannot enter
these full-state rankings. Original full-state model requirements remain open.

The browser shows Best EV and Best arbitrage comparisons immediately. Numeric
zero/negative values use the main list, with negative/zero opposing pairs explicitly
not labeled profitable arbitrage. Prices use the existing American-odds conversion;
inconvertible values say unavailable, with originals retained in evidence.
Filters are secondary. Dashboard Details uses the displayed shared policy,
not a previously saved custom amount. Evidence tokens capture the original full
selected frame from the same database snapshot. Reload shows checking, updated,
checked/no changes, or failed; failure withdraws freshness. The dashboard client
has a five-second read bound; cancellation/resource guards remain in place.

### Contract shared with the planned Odds grid
