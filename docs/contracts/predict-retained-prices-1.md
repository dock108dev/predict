# predict-retained-prices-1

The additive, read-only `/api/current/prices` endpoint serves original retained numerical prices and admission progress. Its [schema](predict-retained-prices-1.schema.json), [compatibility fixtures](../../app/fixtures/retained-prices-v1.json) and [ownership protocol](../estimated-runtime.md) supplement strict complete Current, Comparison and historical contracts.

Query parameters are `settings_generation` (safe nonnegative integer), `page` (0–15,999) and optional `generation_id`. Nonzero pages require the exact generation. Each page has one row, at most 256 KiB including the envelope. This preserves Current's existing 2,048-character native identifiers without allowing a page of long identities to exceed its transport bound. Runtime/generation IDs are at most 160 characters. Maximum inventory is 16,000 rows; state/candidate/row ownership remains within the existing 64 MiB cap. Invalid numeric queries or mismatched generations return 409 with `retained_prices_unavailable`; unknown query fields return 422 and reader capacity returns 429; a refusal is never a completed financial response.

The envelope includes mode (`current` or explicitly authored `synthetic`), runtime, candidate generation, echoed settings generation, server policy, original input clock, actual validation time, status, progress and nullable committed epoch/revision. Only `ready` represents complete successful installation. Pending/rejected/superseded/stopped candidates carry null epoch/revision. Terminal unsuccessful generations have no rows. Financial results remain withheld until complete admission; progress is not a new financial snapshot.

Rows preserve venue, all provider/event/market/outcome/side/quote-side identities, canonical quote ID and revision, original units/value/payout/native transformation and source/receipt/projection clocks. Unknown payout does not make a valid original numerical price disappear. Validation does not renew an observation clock. Native Short/NO bid transformations show the original native price and disclose the acquisition complement.

Exact discovered/validated/ready/refused counters belong to this generation. Unknown totals and pending counts remain null until discovered. Completed evaluation refusals count as refused, not supported estimates. Complete totals reconcile ready + refused + pending, with pending zero. Singles and both-objective pairs retain production engine/search semantics and fair full-slate order.

One server-owned admission job and one latest pending descriptor serve all readers; reads do not create jobs. Each candidate has a 300-second total lease, including at most four eligibility rebases. A true boundary supersedes the old future without acknowledgement and transfers already-owned inputs to a new generation at the actual calculation clock; the original input/quote clocks remain unchanged. Sixteen price readers have a ten-second total lease; EOF, disconnect, timeout, generation replacement and Stop release payloads. No price files or unbounded history are added. Synchronous source commits remain compatible and acknowledge only complete success. Complete encoded transport retains its existing four-file/sixteen-reader pool, 30-second cache and 300-second reader leases.

Odds and EV/Arbs validate schema, mode, exact runtime/generation/settings/policy, progress/counts, identities, numerical units and clocks before adoption. Malformed contracts fail closed. Settings/runtime changes cancel delayed readers. A generation mismatch retries unbound page zero and visibly shows loading. Details uses complete admitted identity and both legs. Browser unit checks simulate delivery; they do not measure actual browser paint time.
